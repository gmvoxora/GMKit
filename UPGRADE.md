# Upgrade to 0.1.0-rc.3

RC3 adds optional `content.command-rewards` without changing SQL schema version 2. Existing kits and configurations do not require new fields; defaults remain empty/disabled. Upgrading from RC2 does not recreate or expose the private starter. Use a full restart and upgrade all network nodes before enabling the feature: RC2 does not understand virtual reward definitions or command-only snapshots. Do not downgrade after granting RC3 command-only rewards. The instructions below also cover upgrading from RC1.

1. Stop every GMKits instance sharing the database. Save a complete server/plugin/database backup. Do not mix RC1 and RC2 in a network: the old code cannot recognize private reward rows. A live instance lease blocks schema migration; after an unclean shutdown allow the old 30-second lease to expire.
2. Replace the plugin with the appropriate **single** Legacy or Modern JAR on each server, then start the upgraded instances. Do not downgrade a version-2 database to RC1.
3. Existing `kits/starter.yml` moves to the independent root `starter.yml`. Its exact original is retained under `history/legacy-starter/`. Custom reward content is retained; public-kit presentation, price and command actions do not become first-join module features. If a private `starter.yml` already exists, it wins and the old public file is archived. Restarting an interrupted migration is safe.
4. Ordinary kits and existing granted rewards remain intact. Existing GMKits accounts are not reclassified as newcomers; their previous starter claim history is retained. An already granted RC1 inbox reward can still be collected normally. A fresh installation includes `kits/adventure.yml`; upgrades do not silently add a public sample kit. `/kit create adventure` can create one if desired.
5. The database gains a version record and operation kind/sender fields. An upgrade with existing data first writes a consistent SQLite backup to `data/backups/`. For network SQL it writes an export ZIP under `backups/`, with one JSON-lines file per plugin table (nulls/numbers/text preserved). That export is evidence/recovery material, not a one-click SQL restore tool. External SQL migration/restore still requires real database testing. Oversized exports fail before altering columns.
6. Run `/kit validate`, inspect its file/item errors, and test a genuinely new account. First-join equipment should arrive with no GUI entry or notification. Test a full inventory: equipment must wait and arrive automatically after space is freed.

`starter.yml` controls `enabled`, `eligibility`, delay/retry ticks, auto-equipment and item content. `NEW_PLAYERS` requires no previous Minecraft server play and no previous GMKits join record. `FIRST_PLUGIN_JOIN` includes existing Minecraft accounts only when first recorded by GMKits. Disabling/re-enabling the module or changing season never resets a completed grant. There is deliberately no player `/kit starter` command or module reset command.

Storage reconnects with backoff after a broken connection. It never changes connections inside an active transaction and never replays an interrupted payment, command or delivery. Such operations still need SECURITY.md reconciliation. Recovered sessions refresh from SQL.

The contents editor copies objects into a draft. Left-click with a cursor item, drag across draft slots, or shift-click your inventory to copy. Right-click clears a draft entry; Undo restores one of five prior drafts. Save opens a confirmation. Closing without saving discards the draft and preserves the source inventory. Existing destinations/preferred slots are kept where valid; new entries use ordinary inventory delivery. Advanced destinations remain configurable in YAML. Full codec support is required to save arbitrary captured objects.

`/kit give <online-player> <kit>` now means a free administrator gift, including from console. It bypasses recipient kit requirements/cost/counters but preserves profile, queue, payload, command-policy and uncertain-operation safety checks. It does not buy future access for the recipient. Logs retain operation kind and sender.
